# Task 3 — E-commerce UI Automation

## Overview

This assignment focuses on implementing an end-to-end UI test for an e-commerce application using Playwright

The target application is [Practice Software Testing](https://practicesoftwaretesting.com/).

The exercise covers a product filtering and sorting workflow, product selection, adding an item to the cart, and validating cart quantity and price calculations.


## Assignment Requirements

The automated test must:

- Be implemented from scratch using the designated automation tool.
- Execute reliably against the target application.
- Handle asynchronous UI updates correctly without hard-coded pauses.
- Implement all required test steps accurately, without skipped, extra, or unnecessary actions.
- Use reliable locators; brittle, absolute, or autogenerated paths are not allowed.
- Keep the code clean and maintainable, with meaningful names and no redundant code, unused code, commented-out code blocks, or debug prints.
- Handle dynamic grid updates and toast notifications using explicit element or state waits.
- Validate data integrity, including numeric price parsing, sorting order, and cart total calculations.

## AI Usage Policy

The assignment permits and encourages the use of AI tools such as GitHub Copilot, ChatGPT, and Claude to assist with drafting code.

The author remains responsible for reviewing the generated code and ensuring that the final implementation is correct, stable, and maintainable.

The assignment also requires incremental, meaningful commits during implementation. Examples include commits for initial setup, locators, filter/sort logic, and cart assertions.

## Target Application

- **Application:** [Practice Software Testing](https://practicesoftwaretesting.com/)
- **Application type:** E-commerce web application
- **Automation framework:** Playwright with JavaScript (as used in this repository)


## Quality and Validation Criteria

- **Execution:** the project builds and executes against the target application without errors.
- **Accuracy:** every specified test step is implemented as written.
- **Locator quality:** use reliable selectors rather than brittle absolute or autogenerated paths.
- **Asynchronous handling:** wait for relevant elements or states; do not use hard-coded pauses as a substitute for synchronization.
- **Data integrity:** parse prices as numbers, validate numerical sorting, and verify that the line total equals unit price multiplied by quantity.
- **Maintainability:** use clear naming and a clean, consistent code structure.
- **Commit history:** make incremental, meaningful commits throughout implementation.
